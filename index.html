Outlook Troubleshooting Guide

In this practice scenario, a user says their Outlook inbox stopped updating this morning. I’d start by checking whether the same account receives mail in the browser. That gives me somewhere to look before asking the user to change anything.

What I’d check

  1. Confirm the user is in classic Outlook for Windows and has the same mailbox open in both Outlook and webmail. The steps below are for classic Outlook.
  2. Ask them to check webmail for a recent message. If there’s no recent message to use, ask them to send a test email from another account they control.
  3. If the test email arrives in webmail, check the status at the bottom of the Outlook window. If it says Working Offline, go to Send/Receive and select Work Offline to reconnect. Then check whether the same test message appears in the app. Microsoft’s guide to working offline in Outlook
  4. If mail is missing in webmail too, check whether it affects every sender or just one. For a single missing message, ask the user to search by sender and check Junk Email. Microsoft’s guide to missing Outlook.com email

What I’d send the user

Hi Sam, could you open the same mailbox in your browser and check if today’s emails are there? If you see them, please tell me what it says at the bottom of your Outlook window. If it says Working Offline, click Send/Receive, then Work Offline to reconnect. Leave Outlook open and check whether the missing messages start coming in.

What I’d include if I escalate

I’d record the Outlook version, when the problem started, whether the test email arrived in webmail, the app’s connection status, and the result of each step. If there’s an error, I’d include the exact wording with any private details removed. That gives the next person enough information to pick up the case.

Sample QA Bug Report

This is a practice bug report for a fictional e-commerce app. The environment and results are simulated.

Field Details
ID DEMO-014
Area Account settings
Environment Demo staging build 0.4.2, Chrome on Windows 11
Frequency 3 out of 3 attempts with the same test account
Suggested severity Medium. Customers can’t reliably update an email preference.

Steps to reproduce

  1. Sign in to a test account with Product updates turned on.
  2. Open Account → Email preferences.
  3. Turn Product updates off and click Save changes.
  4. Wait for the “Preferences saved” message, then reload the page.
  5. Check the Product updates toggle.

Expected result

Product updates stays off after reloading the page.

Actual result

The app says “Preferences saved,” but Product updates is back on after reload. The test only confirmed what the settings page displays. Whether product emails would still be sent needs a separate check.

Retest after the fix

Save the preference as off, then reload the page and sign out and back in to confirm it stays off. Turn it on again and repeat the check to verify the setting saves both ways.
